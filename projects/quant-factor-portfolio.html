Quant Factor-Portfolio Pipeline

Personal project, 2026 Evolved from MFRM Advanced Investments GitHub
End-to-end quantitative factor investment pipeline spanning the full lifecycle: factor construction from Compustat/CRSP data, statistical selection and validation against Capital IQ benchmarks, mean-variance portfolio optimization via convex programming, and Black-Litterman equilibrium with sensitivity analysis.

Origin

This project began as coursework for Advanced Investments during the MFRM at Rotman. The original assignment explored factor-based portfolio construction using academic datasets. I rebuilt and extended it into a production-grade pipeline with a modular architecture, additional factor families, formal optimization, and Black-Litterman integration.

Pipeline Architecture

Stage 1 — Factor Construction
10+ factor families built from Compustat/CRSP fundamentals: valuation, momentum, growth, leverage, earnings quality, risk, sentiment, analyst, price factors. Each factor inherits from an abstract base class for extensibility. Validated against Capital IQ benchmarks via correlation checks.
↓
Stage 2 — Factor Selection
Statistical testing and screening of factor candidates. Cross-sectional sorts and portfolio formation for factor return estimation. Integration with Fama-French factor loadings.
↓
Stage 3 — Portfolio Optimization
Covariance estimation with shrinkage methods. Mean-variance optimization via CVXPY (convex programming). Constraint handling: long-only, turnover limits, sector bounds.
↓
Stage 4 — Black-Litterman
Implied equilibrium returns via reverse optimization: π = δΣwmkt. Market-capitalization weighting. View blending with investor confidence. Sensitivity analysis across risk aversion parameters.

Key Technical Decisions

Why abstract base class architecture for factors?

Each factor implements a Factor ABC with a compute() method that returns a date × asset DataFrame of exposures, and a validate() method that checks correlation against Capital IQ benchmarks. This makes adding new factors a single-file operation with guaranteed interface consistency.

Why CVXPY for optimization?

CVXPY provides disciplined convex programming with constraint handling that would require complex manual implementation with SciPy's minimize. Constraints like long-only, turnover limits, and sector bounds are expressed declaratively, making the optimization transparent and auditable.

Why Black-Litterman?

Standard mean-variance optimization is notoriously sensitive to expected return estimates. Black-Litterman starts from market equilibrium (implied returns from market-cap weights) and blends in investor views with explicit confidence levels. This produces more stable, economically intuitive allocations.
