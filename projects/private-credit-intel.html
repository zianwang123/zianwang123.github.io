Private Credit Intelligence Engine

Personal project, 2026 Evolved from OTPP internship tool GitHub
An agentic document intelligence system that ingests credit agreement PDFs, extracts normalized covenant and pricing terms into structured data, self-verifies uncertain fields through an LLM-as-judge correction loop, grounds every field in source evidence, compares documents across deals, and generates portfolio-level risk analytics.

Origin

In early 2024, as an Investment Risk Analyst at Ontario Teachers' Pension Plan, I built an LLM-powered credit loan agreement review tool using LangChain and GPT-4 with RAG. It reduced review time for 200–300 page agreements from days to 1–2 hours and achieved 99% key term identification across 5 active deals.

That prototype proved the workflow but relied on prompt-heavy parsing, brittle chunking, and loosely structured outputs. This project is the ground-up rebuild — designed for reliability, traceability, and quantitative analytics.

↓
Layer D — Validation
Numeric range checks (%, x, USD, bps, dates) · Citation verification (evidence text ↔ source chunks)
↓
Layer D.5 — Staged Self-Verification (Agentic Loop)
Stage A: Informed verification (temp=0.2) → Stage B: Blind re-extraction (temp=0.7, reversed chunks) → Stage C: Source-grounded judge (temp=0.0)
Deterministic evidence scoring at each stage — 83% resolved without judge call
↓
Layer E — Analytics
Risk scoring (covenant tightness, add-back aggressiveness, lender protection) · Cross-document comparison · Cross-model consensus · Portfolio-level analytics
↓
Output
Streamlit UI · Single document view · Auto-generated term sheet · Risk gauge charts · Side-by-side comparison · Portfolio dashboard

Design philosophy: precision over recall. A credit analyst would rather see “not found” than a wrong value. The system returns not_found for genuinely absent fields — the investment-grade Pepco deal correctly has no EBITDA add-backs, no collateral, no debt baskets, as expected for an unsecured utility term loan.

Key Technical Decisions

Why hybrid retrieval (semantic + keyword)?

Pure embedding-based semantic search has a known blind spot: when a short, high-value definition is embedded in a 4000-character chunk containing 20+ other unrelated definitions, the embedding becomes a diluted average. In testing, the chunk containing “Applicable Rate” ranked 19th out of 475 chunks for the best semantic query — well below the top-10 cutoff.

Keyword search solves this at zero additional API cost and improved field discovery from 29/44 to 38/44 fields (+31%).

Why staged self-verification instead of running twice?

The self-correction literature shows that naive “please reconsider” prompts suffer from anchoring bias (Huang et al. 2024), while structured evidence-based verification improves accuracy reliably (Kamoi et al. 2024).

The staged design is selective (only re-extracts flagged fields, typically 5–15%), evidence-constrained (treats prior answers as falsifiable hypotheses), and uses deterministic fast-pass filtering so most fields resolve without an LLM judge. On the Daseke deal: 5 fields flagged, 83% resolved by deterministic checks alone.

Why dual-provider (OpenAI + Anthropic)?

Running both providers on the same document enables cross-model consensus: fields where both models agree have high confidence, while disagreements flag fields for human review. This provides a confidence signal without requiring ground-truth labels.

Why evidence grounding?

Every extracted field carries evidence_text and page_numbers. The citation check layer verifies that the evidence actually appears in the source chunks. Users can audit exactly what the model read. This catches hallucinated citations — the model cannot claim evidence from text that doesn't exist in the document.

Five-Layer Verification System

Layer What How
1. Schema Enforcement No malformed JSON OpenAI Structured Outputs / Anthropic Tool Use
2. Domain Validation No out-of-range values Numeric range checks + evidence substring matching
3. Self-Verification Agentic self-correction 3-stage escalation: informed → blind → judge
4. Evidence Traceability Every field is auditable Page numbers + evidence text in every extraction
5. Labeled Evaluation Systematic accuracy 132 ground-truth fields, precision/recall/F1
