Causal Sentiment Engine

Personal project, 2026 Built with Claude Code GitHub
A full-stack application that models macro-financial interconnectedness as a 3D interactive causal graph. 52 macro nodes (rates, commodities, equities, currencies) connected by 117 directed causal edges, with an AI agent that fetches real-time data, analyzes sentiment, and propagates shocks through the network.

Origin

Traditional sentiment analysis treats assets in isolation — one stock, one headline, one data point at a time. But a change in CPI expectations propagates through monetary policy, into interest rates, through credit markets, and into equity indices. Macro investors like Bridgewater model these cascading relationships systematically. This project makes that causal map explicit, visual, and interactive.

The idea started with a question: what if you could shock one node — say, drag oil sentiment to −0.8 — and watch the cascade ripple through energy, inflation, rates, and equities? Direct hits, indirect effects, inverse beneficiaries, uncorrelated nodes — all visible in one graph.

AI Agent

The agent runs a three-phase reasoning loop — Plan, Analyze, Validate — with self-calibration. It has access to 11 tools for fetching data from FRED, yfinance, news sources, Reddit, and SEC EDGAR. A full 52-node analysis uses 30–60K tokens per run. The entire orchestrator is ~200 lines in orchestrator.py — no framework abstractions like LangChain, just direct SDK calls.

The provider is switchable at runtime between Claude and GPT. The agent also records falsifiable predictions that the system auto-resolves and tracks for hit rate over time.

Key Technical Decisions

Why a directed causal graph instead of correlation matrix?

Correlations are symmetric and say nothing about causation direction. A directed graph encodes that Fed policy causes rate changes, not the reverse. This lets shock propagation follow real causal channels rather than statistical associations that break down in regime changes.

Why no LangChain?

The agent orchestrator is ~200 lines of direct Anthropic/OpenAI SDK calls. Framework abstractions add indirection that makes debugging harder and limits control over the reasoning loop. The three-phase Plan–Analyze–Validate pattern is simple enough to express directly, and switching providers is just swapping the SDK call.

Why expert-defined edges + dynamic weight learning?

Pure data-driven edge discovery finds spurious correlations. Pure expert definition misses evolving relationships. The hybrid approach starts with 117 expert-defined causal edges, then allows the system to adapt weights and suggest new edges based on observed data — subject to analyst review.
